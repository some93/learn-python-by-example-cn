- 汉诺塔问题

## 🤔 先想一个问题

俄罗斯套娃见过吧？打开一个大的，里面是一个小的，再打开小的，里面还有更小的……直到最里面那个打不开为止。递归就是这个逻辑：**函数调用自己**，每次问题规模缩小一点，直到遇到**最简单的情况**（终止条件）直接返回答案。

## 📖 看代码

```python
# 阶乘 n!
def fact(n):
    if n == 1:        # 终止条件（base case）
        return 1
    return n * fact(n - 1)

print(f"5! = {fact(5)}")      # 120
print(f"10! = {fact(10)}")    # 3628800

# 汉诺塔
def hanoi(n, source, target, auxiliary):
    if n == 1:
        print(f"{source} -> {target}")
        return
    hanoi(n - 1, source, auxiliary, target)
    print(f"{source} -> {target}")
    hanoi(n - 1, auxiliary, target, source)

print("--- 汉诺塔 (3个盘子) ---")
hanoi(3, 'A', 'C', 'B')

# 栈溢出
import sys
print(f"递归深度限制: {sys.getrecursionlimit()}")
# fact(1000) 会报 RecursionError!
```

## 🔍 师兄给你逐行拆

### 阶乘的递归展开

```
fact(5)
= 5 × fact(4)
= 5 × 4 × fact(3)
= 5 × 4 × 3 × fact(2)
= 5 × 4 × 3 × 2 × fact(1)
= 5 × 4 × 3 × 2 × 1
= 120
```

每次调用都会在**调用栈**上压入一层。`n=1` 时触发终止条件，开始逐层返回。**没有终止条件的递归会无限套娃，直到栈溢出**。

---

### 栈溢出 —— Python 的保险丝

Python 默认递归深度限制是 **1000 层**。超过就报 `RecursionError`。你可以用 `sys.setrecursionlimit()` 调高，但**不推荐**——递归太深说明你应该改用循环。

**和 Go 的对比**：Go 的 goroutine 栈可以动态增长到 GB 级别，递归深度限制宽松得多。Python 用的是固定大小的 C 栈，天生不适合深递归。

## 💡 师兄的碎碎念

- 递归优雅但有性能代价：每层调用都要压栈、保存状态。能用循环解决的问题，循环通常更快。
- Python **不支持尾递归优化**（Go 也不支持）。即使你写了尾递归形式，Python 也不会优化掉栈帧。
- 递归的经典应用：树的遍历、分治算法（快排、归并排序）、回溯算法（八皇后、数独求解）。
- 用 `@functools.lru_cache` 装饰器可以给递归函数加**记忆化**，避免重复计算（比如斐波那契数列），后面装饰器那关会讲。

## 🎓 这一关的知识点清单

- **递归**：函数调用自身，必须有终止条件（base case），每次调用缩小问题规模。
- **终止条件**：递归的「出口」，没有它就会无限递归直到栈溢出。
- **RecursionError**：Python 默认递归深度 1000，超过报错。
- **汉诺塔**：经典递归问题，n 个盘子需要 `2^n - 1` 步。
- **递归 vs 循环**：递归代码简洁但有栈开销，循环性能更好但代码可能更复杂。
